# OpenCloud

Files on percolator at `https://opencloud.${DOMAIN}`, using Authelia OIDC.
The built-in IdP is disabled. Internal IDM remains for provisioned account
metadata. Calendars and contacts use the independent Radicale stack; Immich
remains the photo backup. Office, Tika and email are not configured here.

## Bring up

1. Follow the runbook's retirement, LLDAP and route owner steps. Human accounts
   need `${LLDAP_ADMIN_GROUP}` or `${LLDAP_HOUSEHOLD_GROUP}`. Check their LLDAP
   username, name and email before first sign-in; these provision the account.
2. From `stacks/percolator`: `./setup-secrets.sh`, `./render-configs.sh`, then
   `./compose.sh authelia up -d --force-recreate` and
   `./compose.sh opencloud up -d`. Check `./compose.sh opencloud logs --tail 100`.
3. The startup script runs `opencloud init --insecure=false --quiet` only for
   empty data with no generated config. It stops if init fails, if config is
   empty, or if existing data has lost its config. Never force initialization
   over a restore. The generated file is `/srv/data/opencloud/config/opencloud.yaml`.
4. Sign in through Authelia first as an admin, then separately as a household
   user. `proxy.yaml` maps only the admin and user roles, admin first. Users
   without either mapped group get no default role.
5. iPhone: install the OpenCloud iOS app, enter the HTTPS server URL and finish
   browser sign-in through Authelia. In Files → Browse → menu → Edit, enable
   OpenCloud as a location. Verify opening a file from another app.
6. Mac and Windows: install the official OpenCloud desktop client 4.0 or newer
   (needed for WebFinger discovery of our client IDs), enter the
   same server URL and complete browser sign-in. On Windows choose virtual
   files for files on demand; pin a folder locally when it must work offline.

Traefik already aliases `authelia.${DOMAIN}` on `proxy`, so discovery reaches
the IdP through its valid HTTPS certificate. No insecure OIDC bypass is used.
TLS ends at Traefik; the internal service listens on HTTP 9200 without a host port.

## Backups and restore gate

This is not a plain folder tree that can be recovered by copying just visible
files. The `backup` file includes **all** of `opencloud/data` and
`opencloud/config`, including metadata, internal IDM, service-account credentials,
IDs, keys, caches and thumbnails. No uncertain cache paths are excluded.
The node backup also saves `secrets.env.local`. Six runtime signing/transfer/
machine/system credentials are generated by `secrets.conf`; environment overrides
take precedence over values in generated config. The remaining internal IDM
passwords, service-account secret, UUIDs and generated certificates must be
preserved with that config/data pair. Recreating them is not a restore.

**A restore test is required before anyone relies on this service.**

1. With client writes paused, make a restic backup using `sudo ./backup.sh nightly`
   and record its snapshot ID. The normal live backup is not proof that all
   embedded stores form a consistent snapshot; the rehearsal must establish this.
2. Restore that snapshot under an isolated directory, including both data and
   config plus the matching node/app secrets. Do not overwrite the live instance.
3. Use the same pinned image in an isolated test deployment with matching ownership,
   separate storage, no production Traefik labels and no shared internal network.
   Arrange a test OIDC client/URL before login testing; do not run a second public
   instance with the same storage or issuer callback by accident.
4. Re-render CSP/proxy configuration for the test URL, check admin and user access,
   download known files and compare SHA256 checksums. Verify shares, permissions,
   app-token access and another restart. Record commands, snapshot and results in
   the runbook. If consistency fails, design a quiesced backup before production.

## GPX bot over WebDAV

The n8n workflow on grinder belongs to its own repo. Here the supported pattern
is an LLDAP account in `opencloud_bot_accounts`, never the admin group. It also
needs `${LLDAP_HOUSEHOLD_GROUP}` for the **user** role: the special bot group is
an Authelia policy boundary, not a third OpenCloud role. The `household` OIDC
policy still denies bots before its human allow rules. This extra membership
also permits Radicale login under the chosen household LDAP filter. The owner
accepted this on 2026-10-13: `owner_only` confines it to its own collections.
Give the bot only the GPX folder/share it needs; do not share household roots.

Sign in as the bot through the `opencloud` OIDC policy once to provision it.
OpenCloud 7.2.4's auth-app service supports app tokens and is enabled by default.
An operator can issue a time-limited token locally with
`./compose.sh opencloud exec opencloud opencloud auth-app create --user-name=<bot> --expiration=720h`.
Copy the displayed value directly into n8n's credential store as the password,
using the bot username. Do not paste it into this repo or logs. The authenticated
`/auth-app/tokens` API can create/list/revoke tokens as well; impersonation stays off.
Use the folder's WebDAV URL shown by OpenCloud, not a guessed path. Verify listing
and downloading the GPX file from n8n, and verify access to an unrelated folder fails.

App tokens are separate from LDAP passwords. Disabling an external-IdP account
does **not** revoke existing app tokens: revoke them in OpenCloud too, and plan
rotation before expiry. Standard Basic password login is disabled while app
authentication stays enabled. The owner must validate app-token DAV with OIDC
role assignment before switching the workflow.

## Is it working?

- [ ] `./compose.sh opencloud ps` shows healthy; restart retains accounts/files.
- [ ] Web login as admin exposes administration; a household user is not admin;
      an unrelated account is refused. A bot is denied other household OIDC apps.
- [ ] iPhone signs in and OpenCloud appears and works in the Files app.
- [ ] Mac sync and Windows virtual-file hydration work after browser login.
- [ ] A file **over 1 GB** uploads through the Cloudflare tunnel, then downloads
      with the same checksum. Test real clients on mobile data as well as web;
      Cloudflare per-request limits mean total file size alone proves nothing.
- [ ] The GPX bot can read only its intended share using a revocable app token.
- [ ] An isolated restic restore passes the checks above and is recorded.
- [ ] Gatus is green and the owner has tested the alert/recovery path.

## Version checks and gotchas

- Checked 2026-10-13: [production 7.2.4](https://github.com/opencloud-eu/opencloud/releases/tag/v7.2.4)
  is the newest production release in the [upstream lifecycle](https://docs.opencloud.eu/docs/admin/resources/lifecycle/)
  and Docker Hub tags. Compose pins `opencloudeu/opencloud` by tag and digest.
  It supports external OIDC, the `oidc` role driver, auth-app tokens and
  WebFinger client discovery; all configured environment names were checked
  against the release's configuration source. No environment rename is needed.
- [Authelia's guide](https://www.authelia.com/integration/openid-connect/clients/opencloud/)
  tests OpenCloud 7.2.4 / Authelia 4.39.28, now the pair pinned here after merging
  main. The previous version gap is closed. Client and app-token acceptance
  still need live testing; matching versions is not proof of this deployment.
- This changes an undeployed repository definition from rolling to production.
  Do not point this older release at data already used by rolling 8.x.
  For upgrades, follow [the migration and rollback procedure](../../../docs/image-upgrades.md#opencloud-majors).
  With an existing generated config, `prepare.sh` requires
  `OPENCLOUD_UPGRADE_READY=7` in the node's `.env.local`; a fresh install passes.
  Record that baseline after the first successful setup; review and back up
  before acknowledging any new major. Never initialize over restored data.
- The [tagged startup source](https://github.com/opencloud-eu/opencloud/tree/v7.2.4/opencloud/pkg/init)
  defines generated config state; the image includes curl and normally runs as
  UID 1000. Compose overrides it to PUID:PGID, matching `data-dirs`.
- [Auth-app documentation](https://github.com/opencloud-eu/opencloud/blob/v7.2.4/services/auth-app/README.md)
  documents token creation and external-IdP revocation limits.
- Never rotate startup credentials as an incidental reinstall. Restore their
  original values with the data/config; record deliberate rotations separately.
- The public web shell healthcheck cannot validate OIDC, storage or uploads.
  Keep every owner check above open until it has live evidence.
